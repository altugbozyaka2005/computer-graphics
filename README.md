# CGR 2026 coursework renderer (`CGR26_renderer`): Modules 1, 2 and 3

Exam number B248075. The reports are `reports/Module1.pdf`, `reports/Module2.pdf` and `reports/Module3.pdf`.

A physically based renderer written in C++17 using only the C++ standard library.
It reads a subset of the pbrt-v4 scene format and contains two integrators,
selected by the scene's `Integrator` directive:

- `whitted`: Whitted-style ray tracer (WSRT).
- `distributed`: distributed ray tracer (DRT).

## Building

```sh
make -C source            # or: cd source && make
```

This produces `output/CGR26_renderer`. Object files go to `build/`.
Run `make -C source clean` to remove them.

Without `make`:

```sh
cd source
c++ -std=c++17 -O3 -pthread -o ../output/CGR26_renderer main.cpp core/*.cpp geometry/*.cpp render/*.cpp scene/*.cpp
```

## Running the renderer on a scene

```sh
./output/CGR26_renderer scenes/WSRT_simple.pbrt
```

Relative paths inside a scene (textures, meshes, `Include`) are resolved against the
scene file's directory. All outputs go to `output/`, i.e. the executable's directory.
`--outdir` changes this.

| File | Content |
|---|---|
| `<name>.png` | display image (tone mapped and sRGB encoded) |
| `<name>.pfm` | linear HDR radiance (a format pbrt-v4 can also write), for quantitative comparisons |
| `<name>.log` | parse warnings and errors (with `file:line:column`), the scene summary, per-stage timings (parse, render, output) and ray statistics |

`<name>` is the stem of the Film `"string filename"`. If the scene has none, the scene file's stem is used.

Exit codes:
- `0`: rendered, possibly with recoverable errors that are logged.
- `1`: fatal scene error such as a syntax error or a missing file, with no image produced. The log explains why.
- `2`: bad command line.
- `3`: internal error.

Command-line overrides (each is recorded in the log). See `--help` for the full list.

```
--spp N  --sampler independent|stratified|halton  --nojitter  --integrator whitted|distributed
--maxdepth N  --bf N  --lightsamples N  --lightsampling uniform|grid|stratified|halton
--res WxH  --pixelbounds X0,X1,Y0,Y1  --cropwindow X0,X1,Y0,Y1
--accel bvh|objects|none  --splitmethod sah|middle|equal  --maxnodeprims N  --costmap
--threads N  --seed N  --out NAME  --outdir DIR  --ppm  --quiet
```

`--accel` chooses how rays find their closest hit: `bvh` (default, a bounding volume hierarchy),
`objects` (one bounding box per Shape directive, the Module 1/2 renderer) or `none` (every ray against
every primitive). The environment variable `CGR26_ACCEL` sets the same for every render of a script
(`--accel` wins). `--costmap` also writes `<name>_cost.pfm`: per pixel, the ray-box tests (r),
ray-primitive tests (g) and rays (b) per camera ray.

With the stratified sampler `--spp` must be a square (n x n cells). `--seed` changes every random
stream, so two renders with different seeds are statistically independent (used for noise estimates).

```sh

./renderReportedImages.sh 1        # Module 1 only (about 1.5 h)

./renderReportedImages.sh 3        # Module 3 only (about 35 min: 10 min for the three images, the rest timing runs)
```

Modules 1 and 2 are rendered with `CGR26_ACCEL=objects` (the per-object boxes of their checkpoints),
so their images and logged timings are reproduced as reported. With the BVH the images are identical
except for the few pixels where two surfaces meet at exactly the same distance (a tie that the
per-object boxes resolve differently from brute force; the BVH resolves it like brute force).

## Student tests

`studentTests/` holds 21 self-contained tests (Module 3): five camera/intersection tests (silhouettes of
every primitive and transform, field of view on landscape and portrait images, wide angle), four shading
tests compared with pbrt-v4 reference images at labelled pixels (point and spot lights, area lights,
interreflection; one with analytic Phong lobes), and 12 scenes with deliberate errors (syntax, structure,
unknown names, missing files, transforms, out-of-range values). Build the renderer first, then:

```sh
./studentTests/runAllTests.sh                  # or: python3 studentTests/runAllTests.py
./studentTests/runAllTests.sh --renderer /path/to/another/CGR26_renderer --tests 1,7,12
./studentTests/test7/run.sh                    # one test
```

The summary (pass/fail per test and per category, with the errors measured) is written to
`studentTests/runAllTests.log`; outputs, difference images and console output to
`studentTests/results/testN/`. Only Python 3 is needed. `studentTests/README.txt` describes the
tests, the metrics and the conventions another renderer has to follow. The Module 1 checks are run
by `python3 scenes/tools/validate_module1.py` after the validation scenes have been rendered (see above).

## Supported scene format

**pbrt-v4 directives**

- **Transforms:** Identity, Translate, Scale, Rotate, LookAt, Transform, ConcatTransform,
  CoordinateSystem, CoordSysTransform, ReverseOrientation.
- **Render options:** Camera, Film, Sampler, PixelFilter, Integrator, Accelerator (`bvh` with
  `string splitmethod` `sah` (default), `middle` or `equal` and `integer maxnodeprims` (default 4);
  `kdtree` and `hlbvh` fall back to the SAH BVH with a warning; the extensions `objects` and `none`
  select per-object boxes or brute force).
- **Structure:** WorldBegin, AttributeBegin/End, TransformBegin/End.
- **Materials:** Material, MakeNamedMaterial, NamedMaterial.
- **Other:** Texture, LightSource, AreaLightSource, ObjectBegin/End, ObjectInstance, Include, Import.
- **Recognised and ignored with a warning:** ColorSpace, Option,
  Attribute, media directives, TransformTimes, ActiveTransform.
- Any other directive, or a malformed one, is logged as an error with its location.

**Objects**

| Kind | Supported |
|---|---|
| Camera | `perspective` (`fov`, `lensradius`, `focaldistance`, `screenwindow`, `frameaspectratio`), `orthographic` (the same without `fov`; the screen window is in camera-space units) |
| Shapes | `sphere` (partial spheres too), `disk`, `trianglemesh`, `bilinearmesh` (triangulated), `plymesh` (ascii and binary), plus the extensions `objmesh` and `plane`. Any shape can take an alpha cut-out mask (`"float alpha"` or `"texture alpha"`, threshold 0.5) that applies to camera and shadow rays |
| Lights | `point`, `spot`, `distant`, `infinite` (constant `L` only), and `AreaLightSource "diffuse"` on any finite shape |
| Materials | `diffuse`, `dielectric`, `conductor`, `interface`, an approximation of `coateddiffuse`, plus the extensions `phong`, `blinnphong` and `mirror` |
| Textures | `imagemap` (PPM/PFM), `checkerboard` (2D), `constant`, `scale`, `mix` |
| Sampler | `independent` (`pixelsamples`), `stratified` (`xsamples`, `ysamples`, `jitter`), `halton` (`pixelsamples`, `randomization` none or a per-pixel shift); `zsobol`, `sobol`, `paddedsobol`, `pmj02bn` fall back to `halton` |
| PixelFilter | `box` (`xradius`, `yradius`: samples drawn from [-r, r]² around the pixel centre); other filters fall back to box with a warning |
| Film | `rgb` with `xresolution`, `yresolution`, `filename`, `cropwindow`, `pixelbounds` |

**Renderer extensions**

These are not in pbrt-v4, so scenes that use them only work with this renderer.

- `Integrator "whitted"` and `Integrator "distributed"`.
  - `whitted`: `integer maxdepth`, `rgb ambient`, `bool transparentshadows` (default false: filtered
    shadow rays that pass through dielectrics, attenuated by Fresnel transmission and `Kt`).
  - `distributed`: `integer maxdepth` (MD), `integer lightsamples` (shadow rays per area light),
    `integer branchingfactor` (BF, default 1: rays per diffuse/glossy scattering event; a camera
    ray spawns up to BF^d rays at depth d; with BF >= 2 a dielectric traces reflection and refraction
    together), `string lightsampling` (`uniform` default, `grid`, `stratified`, `halton`: the pattern of
    the shadow-ray samples on each area light; `grid` and `stratified` use n x n samples with
    n = round(sqrt(lightsamples))) and `string haltonrandomization` (`cp` default: a random toroidal
    shift per shading point; `none`).
    Optional for the DRT (all off by default):
    `bool transparentshadows` (filtered shadow rays through glass, as in the WSRT; light that reaches
    a lamp by refraction after a diffuse bounce is then not counted again),
    `float minweight` (stop a path once its throughput falls below this value, e.g. 0.001), and
    `bool caustics` (false: light reaching a lamp via a mirror or glass after a diffuse bounce is
    not counted; removes rare bright speckles at the cost of that light).
- `Material "blinnphong"` / `"phong"`:
  - `rgb Kd` or `texture Kd`
  - `rgb Ks`, `rgb Ka`, `rgb Kr`
  - `float shininess` (or `exponent`)
  - `bool normalized`
- `Material "mirror"`: `rgb Kr`.
- `Shape "plane"`: `point3 p`, `normal n`. The plane is infinite and gets planar UVs.
- `Shape "objmesh"`: `string filename`.
- Film tone mapping:
  - `string tonemap` (`reinhard` | `none`). The default is `reinhard` for the DRT and `none` for the WSRT.
  - `string tonemapmode` (`luminance` | `rgb`).
  - `float whitepoint` (0 = automatic, i.e. the maximum scene luminance).
  - `float key` (Reinhard's photographic key, 0 = off).
  - `float exposure`.
- `AreaLightSource "diffuse"` also accepts `integer samples`, a per-light override of `lightsamples`.
  `samples 0` makes a visible-only emitter: seen directly and in mirrors/glass, but it does not
  light the scene (for small decorative lights whose illumination is negligible).

## Known limitations

- Pixel reconstruction is a box filter (equal weights). pbrt-v4's default Gaussian filter is not
  implemented, so pbrt scenes without a PixelFilter look slightly sharper than in pbrt.
- The DRT samples indirect directions uniformly over the hemisphere (BRDF importance sampling is the
  final phase), so glossy surfaces need many rays (BF x spp).

- The BVH is built once, single-threaded, over the bounded primitives (spheres, disks, triangles);
  infinite planes are tested against every ray. Object instances are expanded into their shapes (no
  shared sub-trees), and there is no kd-tree or HLBVH (both fall back to the SAH BVH).
- Primitives whose bounding boxes overlap heavily (e.g. long thin triangles crossing one region,
  `scenes/acc_worst.pbrt`) gain little from the BVH: rays still visit most of its leaves.
- Rendering is in RGB, not spectrally. Spectra (blackbody, named spectra, sampled spectra)
  are converted to RGB with an analytic CIE fit.
- Rough conductors and dielectrics are rendered as smooth ones. `coateddiffuse` and named
  metals are approximations (all logged). Media, displacement and normal maps,
  environment maps, and image area lights are not supported.
- Image textures must be PPM (P2/P3/P5/P6) or PFM. PNG and EXR are not read.
- In the WSRT, area lights act as point lights at their centroid (hard shadows). Dielectrics cast
  opaque shadows unless `transparentshadows` is on; even then the shadow rays travel in straight
  lines, so refraction caustics (focused light) are not produced.
- Alpha masks: only a shape's nearest hit is tested against the mask (exact for triangles).
